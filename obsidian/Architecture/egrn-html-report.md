# HTML-отчёт по объекту: граф, хронология, эссе

**Код:** `parser/egrn_parser/exporters/html_report.py` · **Шаблон:** `parser/egrn_parser/templates/object_report.html.j2`
**Связанные:** [[egrn-geo-pipeline]], [[ADR-008-manual-contours-and-conflicts]], `parser/scripts/04_nspd_graph_v14.py`

## Что это и чем отличается от 04_nspd_graph

`04_nspd_graph_v14.py` (2 400 строк) строит граф **проекта** из выгрузки НСПД —
ему нужен пройденный конвейер 01–03 и `enriched_*.json`. Этот отчёт решает
более раннюю задачу: выписки только что разобраны, проекта ещё нет, источник —
SQLite, единственное, что к этому моменту существует.

Один самодостаточный HTML, три вкладки:

| Вкладка | Отвечает на вопрос | Чем сделана |
|---|---|---|
| Права и ограничения | кто с кем связан | vis-network, палитра из 04 |
| Хронология | что за чем шло | разметка + CSS, без библиотек |
| Эссе | что это за объект словами | `essay_md` → HTML + выгрузка `.md` |

Граф и хронология — **разные вопросы**, и один ответ на оба не работает: из
графа не видно, что обременение возникло через 19 лет после права, а из
хронологии не видно, что оба относятся к одному правообладателю.

## Данные и вёрстка разделены намеренно

`build_report_data(conn)` возвращает словарь; ни одной строки HTML в нём нет.
Данные тестируются построчно (`tests/test_html_report.py`), вёрстка ломается
иначе и заметна глазом. Jinja2 (уже в зависимостях) рендерит шаблон.

В страницу данные уходят дважды: развёрнутыми переменными — для разметки, и
одним `data_json` — для скриптов. Второе нужно, чтобы кнопка выгрузки отдавала
**исходный markdown**, а не пересказ вёрстки, собранный обратно из DOM.

## Что граф показывает честно

Право и обременение лежат в `rights` рядом, но это не однородные записи: одно
говорит, чей объект, другое — что с ним нельзя сделать. Поэтому у них разные
категории, разные цвета (`#6baed6` против `#3182bd`) и разные типы рёбер.
Слить их в «связи объекта» значит потерять ровно то, ради чего граф и строят.

Палитра целиком взята из `04_nspd_graph_v14.py`. Свои цвета здесь заводить
нельзя: один и тот же тип объекта обязан выглядеть одинаково в обоих графах
системы, иначе человек, работающий с обоими, начнёт путаться.

**Персональные данные.** Правообладатель-физлицо — узел «Физическое лицо» без
имени: он нужен, чтобы видеть долевую собственность, а ФИО, СНИЛС и паспорт в
отчёте не нужны никогда. Юридические лица называются — они публичны по ЕГРЮЛ, и
без имени обременение нечитаемо («в пользу кого залог?»). Из слипшейся строки
`beneficiary_name` (имя, ИНН, ОГРН, почта, адрес) в граф идёт только имя.

## Хронология

Источники событий: постановка на учёт, регистрация прав и обременений, выписки,
контур из выписки, ручная обводка, обнаружение и разрешение конфликта контура.

События **без даты выбрасываются**, а не сваливаются в начало: «неизвестно
когда» на шкале времени изображается только враньём. Цвет события совпадает с
цветом соответствующей категории графа — одно явление не меняет цвет при
переходе между вкладками.

## Самодостаточность

По умолчанию vis-network **вшивается** в файл (`parser/vendor/`, ~0,7 МБ):
отчёт открывают на объекте, где сети может не быть, а страница, показывающая
без интернета пустой прямоугольник вместо графа, бесполезна ровно тогда, когда
нужна. `inline_vis=False` переключает на CDN и даёт файл ~30 КБ.

Граф строится при первом показе вкладки, а не при загрузке страницы: раскладка
на холодном старте заметно думает, и незачем платить этим тому, кто пришёл
читать эссе.

## Выгрузка эссе

Три кнопки: «Скачать .md» (отдаёт исходный markdown из `data_json`),
«Скопировать текст» (с откатом на `execCommand` — файл открывают с диска по
`file://`, где `navigator.clipboard` недоступен, и это штатный случай) и
«Печать».

## Markdown → HTML своим конвертером

Подмножество, которое реально порождает `essay_md`: заголовки, таблицы, списки,
цитаты, `**жирный**`, `*курсив*`, `код`. Тянуть библиотеку ради закрытого
набора конструкций, который пишет этот же проект, незачем. Если `essay_md`
начнёт выдавать что-то ещё — придётся добавить сюда, и это честнее, чем молча
рендерить неизвестный синтаксис как попало. Всё, что приходит из базы,
экранируется: в адресе может оказаться `<`, и это не разметка.

## Запуск

```bash
python parser/scripts/01e_egrn_pipeline.py --xml <папка> --db egrn.db --out выгрузка/
# только отчёт, без KML и эссе:
#   --no-kml --no-essays --no-schema-doc
```
В окне — галка «Собрать HTML-отчёт» на первой вкладке и кнопка «Открыть отчёт»
на второй.
