# 2026-08-20 — новый интерактивный скрипт: kml_extract_cadastre_numbers.py

## Задача
Пользователь попросил отдельный скрипт: запускается, спрашивает путь к
KML в консоли (без флагов), читает файл, вытаскивает кадастровые номера,
выводит список — и сохраняет в файл `<имя>+<расширение>` рядом с
исходным (уточнено вопросом: список — просто вывести, не интерактивно
проходить по каждому номеру; имя выходного файла — `Олимп+.kml`, '+'
перед расширением, не после).

## Что сделано
`parser/scripts/kml_extract_cadastre_numbers.py` (новый) — тонкая
интерактивная обёртка над уже существующим
`kml_apply_nspd_contours.list_cadastre_numbers()` (переиспользует
функцию, не дублирует regex/логику извлечения КН — тот же принцип, что
уже применён между тестами и скриптами в этом репозитории). Спрашивает
путь через `input()` (переспрашивает на пустой ввод/несуществующий
файл, снимает кавычки — частый случай copy-paste пути из Windows),
пишет уникальные КН по одному на строку в `<стем>+<расширение>`
(`Олимп.kml` → `Олимп+.kml`) и дублирует список в консоль.

`README_NSPD_CONTOURS.md` — новая строка в таблице скриптов + альтернатива
в разделе быстрого старта.

## Как проверялось
`pytest parser/tests/test_kml_extract_cadastre_numbers.py` — 5/5
(`output_path_for`, приём валидного пути, снятие кавычек, переспрос на
пустой/несуществующий путь, `main()` целиком — файл записан, содержимое
и консоль совпадают). Плюс реальный прогон через настоящий stdin
(`echo путь | python kml_extract_cadastre_numbers.py`) на присланном
пользователем KML — 22 номера, файл `Олимп_20-08-2026_11-16-09+.kml`
записан рядом с исходным, содержимое совпадает с выводом в консоль.
