# 2026-08-20 — kml_apply_nspd_contours.py: README + UX-фикс по реальному запуску

## Задача
Пользователь прогнал `kml_apply_nspd_contours.py` (PR #134) первым делом
на реальном KML и упёрся в `contours.json не найден` — ожидаемо (шаги
1-2 конвейера ещё не выполнены), но сообщение не объясняло, что делать
дальше. Попросил: пояснить как пользоваться, проверить/обновить скрипт,
записать в README.

## Что сделано
- `parser/scripts/kml_apply_nspd_contours.py`:
  - Новый флаг `--list-cadastre-numbers` — печатает уникальные КН из
    полигонов KML (готовый список для вставки в интерактивный
    `01_parsing_nspd_v8.py`, разделитель — перевод строки, тот же
    формат, что принимает его `read_cn_batch()`). `--contours`/`--out`
    для этого режима не нужны — раньше были жёстко обязательными.
  - Сообщение об отсутствующем `contours.json` теперь пишет точные
    следующие команды (шаг 1, шаг 2, с путём именно к тому файлу и
    KML, что передал пользователь), а не просто "не найден".
- `parser/scripts/README.md` (новый) — весь конвейер: таблица
  скрипт→назначение→где запускать, быстрый старт на PowerShell (с
  тем же путём `E:\Code\ekcelo\...`, что в реальном запуске
  пользователя) и bash, разбор трёх причин "КН не заменился" (нет в
  реестре / screenshot_cv без геореференса / нет КН в description),
  идемпотентность шага 2.
