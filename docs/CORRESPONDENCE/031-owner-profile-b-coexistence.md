# 031 — Профиль B (активы инвентаризации) — сосуществование с Профилем A в CONTRACT_KMZ.md

- **From:** owner
- **To:** parser, viewer
- **Date:** 2026-08-21
- **Re:** CONTRACT_KMZ.md §2/§5/§6; `ekcelo-site/docs/CONTRACT_KMZ.md` (2.13.0 → 3.0.0)
- **Status:** ratified (single-owner mode, §3.6)

## Суть (выжимка; источник истины — CONTRACT_KMZ.md / по ссылкам)

Сквозной аудит семьи EkceloFoto (2026-08-21, задача пользователя «проверь
идемпотентность форматов») обошёл все реализации KMZ и обнаружил, что
`ekcelo-site/docs/CONTRACT_KMZ.md` версии 2.13.0 документировал «Профиль B»
(активы инвентаризации: `EkceloFotoMakeInvent`, `EkceloFoto Mobile`,
`VineInvent`, `iarobo-welcard`) — формат, который ни разу не совпадал ни с
одной реальной реализацией writer'а. `ekcelo-site/docs/CONTRACT_KMZ.md`
переписан до **3.0.0** с единой консенсусной схемой (Placemark-гранулярность
«1 запись = 1 Placemark», единый набор `ExtendedData` включая `accuracy_m`,
приоритетный сайдкар `ekcelo.json` с запретом отказа по `contract`/`org_id`,
зарезервированный `styleUrl`-префикс `inv_*`, формализация `VineInvent`/
`iarobo-welcard` как полноправных эмитентов). Полное нормативное тело —
там, §4–§7.

`ekcelo/docs/CONTRACT_KMZ.md` (2.12.0, ратифицирован PR #1) — узкий скоуп
(§2: «Контрактная поверхность — ТОЛЬКО KMZ-архив» парсера, `doc.kml` +
`images/` + `docs/` + `graph.html`) — не переопределяется. Профиль B не
эмитируется парсером и остаётся ЗА пределами §2, но физически может
оказаться в ОДНОМ `.kmz`-файле вместе с Профилем A (когда пользователь
объединяет кадастровую выгрузку с инвентаризационной в одном контейнере
для просмотра в `?mode=pro`), поэтому этот файл обязан хотя бы формально
знать о его существовании — иначе §5/§6 (запрет HTML/`<img>` в
description, 9 `styleUrl`-префиксов) читаются как противоречащие живому
коду `EkceloFotoMakeInvent`/мобильного, хотя на самом деле относятся к
другому домену.

Это давно обещанный, но не выполненный «handoff команде parser» —
статус-блок `ekcelo-site`-файла обещал его при «следующей синхронизации
`contracts/`» ещё в 2.12.0/2.13.0; синхронизации не происходило.

## Решение (COMMENT-review чеклист, §3.6 single-owner mode)

- [x] Новый **§11 «Профиль B — активы инвентаризации»** в
  `ekcelo/docs/CONTRACT_KMZ.md`, без renumbering §1–§10. Признаёт Профиль B
  отдельным, параллельно сосуществующим доменом (эмитенты — не parser);
  указывает `ekcelo-site/docs/CONTRACT_KMZ.md` §4–§7 как нормативное тело
  по ссылке (не дублируется).
- [x] `styleUrl`-префикс `inv_*` зарезервирован за Профилем B, явно не
  пересекается с 9 префиксами §6 (`cad_*`/`photoPin_`).
- [x] §5/§6 (запрет HTML/`<img>` в `<description>`) уточнены как
  применимые **только** к Профилю A — это не смена самого запрета (он
  остаётся byte-stable для Профиля A), а формальное признание границы
  области действия, которая де-факто существовала и раньше.
- [x] Версия контракта 2.12.0 → **2.13.0** (MINOR по правилу §4 — новый
  опциональный домен/префикс, обратная совместимость не нарушена: старый
  парсер/viewer, не знающий про Профиль B, продолжает работать как раньше).
- [x] Новая строка в таблице §10 «Изменения».

Домен решения — кросс-доменный (§3: и данные, и UI/UX одновременно
затронуты косвенно), но не создаёт конфликта интересов между командами
(добавление ссылки, не переопределение существующих данных/UI-инвариантов),
поэтому ratified сразу владельцем как арбитром, single-owner mode §3.6,
формой (2) — этот COMMENT-review чеклист.
