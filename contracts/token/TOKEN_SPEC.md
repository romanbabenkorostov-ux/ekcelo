# C7 — Токен доставки проекта (ekcelo.ru/?t=…)

**Версия:** `token 3.1.0` (пакет `contracts 1.2.1`). **Эмитенты:** админ-страница
`admin-encode.html` (ekcelo-site), `tools/ekcelo_tokens.py` (ekcelo). **Проверяющий:**
Cloudflare-воркер `infra/cloudflare-worker/worker.js` (маршрут `/token`).
**Потребители:** лендинг (`tokens.js`, поле токена в шапке), вьюер `viewer/` (`?t=`).

## 1. Зачем v3

Комплект проекта — это два файла рядом: отчёт HTML и слой KMZ (abn, ADR-015; cca, EFMI,
VineInvent — тот же C1 KMZ). Владелец кладёт их в **одну публичную папку Яндекс.Диска**
и отправляет получателю ссылку `https://ekcelo.ru/?t=<токен>`.

Токен v2 — это просто `base64url(URL)`: кто угодно может собрать токен на любую ссылку,
срок у него не ограничен, и его можно незаметно отредактировать. В v3 к токену добавлены
подпись (HMAC), срок действия и пути к **обоим** файлам комплекта. v2 продолжает
работать без изменений: изменение аддитивное.

## 2. Формат (нормативно)

```
токен v3 = <payload> "." <sig>
payload  = base64url(UTF-8(JSON))            без "=" в конце
sig      = base64url(HMAC-SHA256(secret, payload_ascii)[0:16])   ровно 22 символа
```

В токене v2 точки нет никогда (алфавит `[A-Za-z0-9_-]`), поэтому версия определяется
**по наличию точки**.

JSON (порядок ключей подписи не касается: подписывается строка `payload` как есть):

| Ключ | Обяз. | Значение |
|---|---|---|
| `v` | да | `3` |
| `pk` | да | публичная ссылка на ПАПКУ Яндекс.Диска (`https://disk.yandex.ru/d/…`, `disk.yandex.com`, `yadi.sk`) |
| `kmz` | ≥1 из двух | путь слоя внутри папки, с `/` в начале: `/Контуры_<проект>_<дата>.kmz` |
| `html` | ≥1 из двух | путь отчёта внутри папки: `/<Отчёт>_<проект>_<дата>.html` |
| `name` | нет | название проекта для заголовка вьюера |
| `exp` | нет | последний день действия `YYYY-MM-DD` (включительно, до 23:59:59 МСК) |

Персональные данные физлиц в токен не кладутся. `name` — это название проекта, а не ФИО.

**Секрет** — строка ≥ 16 символов. Хранится только:
- в воркере, в переменной окружения `TOKEN_SECRET` (Cloudflare → Workers → ekcelo-proxy →
  Settings → Variables → Encrypt). Это бесплатно;
- у того, кто выпускает токены: переменная окружения `EKCELO_TOKEN_SECRET` для
  `ekcelo_tokens.py` или поле «Секрет» на `admin-encode.html` (страница его не сохраняет).

Если секрет сменить, все выпущенные токены v3 разом перестанут открываться. Так их
отзывают.

## 3. Проверка — воркер `GET /token?t=<токен>`

| Ответ | Когда |
|---|---|
| `200 {"v":3,"name","exp","kmz":{"path","href"},"html":{"path","href"}}` | подпись верна, срок не вышел; `href` — разовая ссылка скачивания Диска (`public/resources/download?public_key=&path=`) |
| `400 {"error":"bad_token"}` | не v3, битый base64/JSON, нет `pk` или ни одного пути, `pk` не на Диске |
| `403 {"error":"bad_signature"}` | подпись не сошлась |
| `410 {"error":"expired"}` | `exp` прошёл |
| `500 {"error":"no_secret"}` | у воркера не задан `TOKEN_SECRET` |
| `502 {"error":"disk"}` | Диск не отдал ссылку (файл переименован, папка закрыта) |

Подпись сверяется за постоянное время. Сама ссылка `pk` в браузер не возвращается:
наружу уходят только разовые `href` от Диска.

**`GET /file?t=<токен>&f=html|kmz`** — сам файл, а не ссылка (token 3.1.0, аддитивно).
Разовая ссылка Диска привязана к тому, кто её запросил, то есть к воркеру: открытая
в браузере получателя, она отвечает ошибкой соединения. Поэтому воркер в одном и
том же запросе берёт свежую ссылку и отдаёт файл с `Content-Disposition: attachment`
и исходным именем. Ошибки — те же, что у `/token`, плюс `400 {"error":"bad_file"}`
(в токене нет такого файла). `href` в ответе `/token` остаётся для совместимости;
вьюер на неё не полагается.

## 4. Поведение потребителей

- **Лендинг** (`tokens.js`): `extractToken` принимает точку, `resolveToViewer` для v3
  ведёт на `/viewer/?t=<токен>`. Сам лендинг подпись не проверяет — секрета у него нет.
- **Вьюер:** токен с точкой → `/token` воркера → KMZ открывается как проект. Если в
  токене есть HTML, появляется кнопка «📄 Отчёт HTML» — это скачивание через
  `/file` (KMZ тоже берётся через `/file`, прямая ссылка — запасной путь); после скачивания отчёт открывается из папки рядом с KMZ,
  как в обычном комплекте. Кнопка «Поделиться» копирует тот же токен v3, а не ссылку на
  Диск.
- **Эмитенты:** имена файлов берутся из комплекта как есть (abn: папка `Передача_…`,
  ADR-015), поэтому файлы на Диске переименовывать нельзя. Переименовали — выпустите
  токен заново.

## 6. Порядок выдачи (для владельца)

1. Собрать комплект (abn «Сборка комплекта» → папка `Передача_…`: HTML + KMZ).
2. Загрузить ОБА файла в одну папку Яндекс.Диска → «Поделиться» → скопировать
   публичную ссылку на ПАПКУ.
3. Открыть `ekcelo.ru/admin-encode.html`: ссылка на папку, пути файлов, срок, секрет →
   «Сгенерировать». Либо в консоли:
   `EKCELO_TOKEN_SECRET=… python tools/ekcelo_tokens.py v3 --pk <ссылка> --kmz /… --html /… --exp 2026-12-31`.
4. Отправить получателю короткую ссылку `https://ekcelo.ru/?t=…` (или QR-код).
